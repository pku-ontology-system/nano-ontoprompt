# 模块接入说明

本文件只约定怎样接入共同平台，不设计各模块内部功能。当前只有导航与本地交互，旧系统不会因入口存在自动接通。

## 代码放哪里

- 平台前端：`apps/platform-web`。模块新增页面放 `src/modules/<模块名>/`；现有公共页面不要求本次全部搬目录。
- 后台：接入时确认放在根目录 `backend/` 的相应模块分区，或确需独立运行的 `services/<服务名>/`，在PR中解释即可。本文件不要求先实现后台，也不规定所有模块同一种技术栈。
- 模块不复制全平台侧栏、登录或账户，不直接读写其他模块内部状态。需要公共改动时在PR中说明影响。

## 入口与资源

`src/module-registry.json`登记固定工具ID、名称、分类、目标页面和接入状态；`src/catalog.json`维护展示说明。当前ID明确保存，排序变化不能更换原有ID，重命名显示名称不能悄悄改变收藏和旧链接。

现有 `#/tool/t10?resource=…` 等链接须兼容；当前公共路由在App.tsx。新增模块在自己的目录实现后，由公共路由分发，保留同一平台导航。特殊公共入口如工作台和模板沿用已有地址。接入状态只用于开发记录，不在UI新增制作标签。

真实接入时用模块的真实资源ID；必要时携带版本、所属本体或容器。现有示例project字段不是后台项目权限模型，不能直接拿示例值冒充正式ID。缺少公共模型时由接入PR明确映射，不本次提前定义新数据库。

## API 权限 跳转和返回

把真实API访问集中在模块的api适配文件；说明调用地址、实际返回、身份传递与失败处理，复用后台已验证的API定义，不另写一套重复权威接口。不把API密钥放进前端。开发环境地址配置若需要，提交不含密钥的.env.example。

权限由服务端校验，前端隐藏不是授权。当前本地admin和signedIn仅支撑导航交互，不是生产登录。接入时补真实身份与无权状态，不直接信任浏览器本地值。

跳转使用现有来源返回机制，只接受平台内路径；链接包含打开目标所需的最少信息。返回恢复原筛选，刷新和直接链接仍可定位；不传敏感数据或任意外部返回地址。资源不存在、无权、暂不可用时给明确反馈，不伪造成功。

## 工作台和MCP只需考虑并说明

作者需要回答：这个模块是否有能力适合在应用搭建工作台复用，或供Agent通过MCP调用？如需要，说明拟提供什么和限制；暂不需要或暂未确定，写原因/后续判断即可。本文件不规定某项功能必须组件化或MCP化，也不要求每个按钮都变成工具。

## 每次接入PR填写这几项

- 需求/批准设计、模块负责人、旧代码来源分支及SHA；哪些复用、哪些改造。
- 页面目录、稳定入口、真实资源ID与调用的API；权限和跨模块影响。
- 工作台/MCP是否需要支持的判断。
- 真正接通的操作、尚未接入的能力；运行和验证步骤。
- 正常操作以及无权/失效资源、刷新、直接链接、返回恢复等适用检查的证据。

无需现在把全部模块重新设计。由负责人对照需求检查，有缺口再补设计，验证通过再提交接入；不能整包拷贝旧平台或假装已有真实后台。
