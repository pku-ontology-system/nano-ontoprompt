# 使用说明（简版）：本体图谱平台——数据源、本体建模、数据分析

> 2026-11-10 · 对应分支 `feat/meeting-demo-features`。只写现在侧栏里能点到的功能，暂时隐藏的入口见第 3 节末尾。设计和取舍见 [ADR 0022](../adr/0022-analysis-after-construction.md)、[0023](../adr/0023-analysis-on-platform-ontologies.md)、[0024](../adr/0024-generic-data-import.md)；以后的数据底座见 [0025](../adr/0025-future-data-platform-duckdb-dagster.md)。

## 1. 打开系统

| 要做什么 | 怎么做 |
|---|---|
| 打开 | 浏览器访问 <http://127.0.0.1:25173>，已登录就直接进入，先看到首页大屏 |
| 登录 | 管理员账号写在项目根目录 `.env` 的 `FIRST_ADMIN_USER` 和 `FIRST_ADMIN_PASSWORD`，只在本机用 |
| 页面打不开 | 在项目根目录执行下面的命令，等约 1 分钟 |
| 改了后端代码 | `docker restart p4int-backend-1`（后端不会自动重载；前端会自动刷新） |

```bash
docker compose -p p4int -f docker-compose.yml -f docker-compose.local.yml -f docker-compose.p4int.yml up -d
```

端口 15173 和 18080 是另一套环境（p4dev），不要动。

## 2. 一句话

数据从**数据源**导入，变成**本体**里的对象，再由**数据分析**的四个页面检查、找重复、画血缘。整条线上的东西都是同一批真实对象：数据源里导入的本体，在本体建模里完整可见，数据分析里直接可选，不是另外一套模拟数据。

首页是一块大屏：本体、对象类型、对象、关系类型的数量，各本体的对象数，当前本体的类型关系图（上方可以切换本体），数据健康通过率，最近的分析，以及“数据源 → 对象类型 → 对象 → 关系类型 → 血缘作业 → 分析运行”的流向。右上有进入数据源、本体建模、数据分析的快捷按钮。数字都是实时从系统里读的。

## 3. 侧栏每个入口

| 入口 | 干什么 |
|---|---|
| 首页 | 上面说的大屏 |
| 本体库 | 全部本体的列表：创建本体，按 ID、名称、创建时间筛选，查看，删除（删除不能撤销） |
| 数据源 | 导入数据建成本体（第 4 节）。不依赖“当前本体”，每次导入建一个新本体 |
| 本体总览 | 当前本体的概况：对象类型、链接类型、运行规则、待处理告警的数量，以及每个对象类型 |
| 对象类型 | 已发布的对象类型：属性、关系、真实记录、证据的数量；展开看记录和来源证据 |
| 数据模型 | 真实对象画成关系画布，可按类型筛选、分批加载；右侧是数据检查器 |
| 数据健康、实体消歧、数据血缘、流水线演示 | 见第 5 到 8 节 |
| 设置 | 通用、构建默认值、模型辅助、证据与质量、数据源、数据权限、数据平面、置信度规则、用户管理、服务主体、提示词模版 |

页面顶部的“当前本体”下拉决定本体总览、对象类型、数据模型看哪个本体；数据分析的四个页面各有自己的“选择本体”卡片，可以自由选哪个本体、哪个对象类型。右下角的“？”是应用自带的帮助。

侧栏里暂时隐藏了一批入口（对象浏览器、关系图、函数、情景推演、决策、规则、告警、Workshop、智能体等），页面都还在：地址后面加 `?nav=all` 全部显示（浏览器会记住），加 `?nav=default` 恢复。

## 4. 数据源：导入任何数据，建成本体

打开“数据源”，有两块：

**演示数据集**（五份，来源和类型各不相同，见第 9 节）：每张卡片写着它是什么、能看到什么、数据从哪来。点“导入这份数据”，页面上会逐步显示导入过程——读取数据、识别类型主键和关系、创建本体、发布对象类型和关系、写入对象、建立关系、核对结果、生成数据血缘，每一步有用时和说明；通常 1 到 3 秒。导入完成后卡片上直接给出“本体总览”“数据模型”“数据血缘”的链接。已经导入过的会标“已导入”，可以“重新导入”（会替换同名本体）。

**导入你自己的数据**：把文件拖进来，或点击选择。没有格式要求：

- CSV、TSV、Excel、JSON、JSON Lines、Parquet 读成表（中文常见编码也能读）；
- 图片、音频、视频、PDF、文档等其他文件记成“文件资产”对象，保存文件本身，可以预览；ZIP 会先展开；
- 表里有一列装着文件名，会自动和文件资产连起来。

读完先给你看识别出了什么（每张表对应的对象类型、主键、行数、识别出的关系、各种文件的个数），改好本体名称再点“开始导入”。勾选“把一张表当事件流，按顺序逐步载入”，可以选事件表、排序列和每批条数：先载入第一批，之后逐批推进。

**逐步载入（动态数据）**：导入后的卡片上有“事件流”面板，显示“已载入 400 / 10,000 条”。点“推进 400 条”载入下一批，或“自动播放”每隔一会儿推进一批；对象和关系随之增长，数据分析里的数字也跟着变。这是真实数据的逐步载入，不是模拟创建。

页面底部折叠着“专用格式的导入器”（时序、多模态、动态数据的旧向导），只在你的数据正好是那种格式时用。

## 5. 数据健康

用“期望”逐条检查一批数据：哪些列不能空、取值在什么范围、哪些值不该出现。每条期望说清有多少行不符合，并举出样例。

1. **选来源。** 默认是“本体里的对象”：选一个本体，再点一个对象类型卡片（卡片上写着属性数和对象数；没有对象的标黄；对象多于 200 个的会写预计读取时间）。切到“开源项目的示例文件”可以用三个开源项目自带的数据（出租车数据、Splink 的 fake_1000、Marquez 的外卖业务）。
2. **看“期望套件”。** 是一段 JSON，每条是 `{expectation_type, kwargs}`，可以直接改。本体来源的套件上方写着“共 N 条：X 条由本体推出”，每条结果带“本体定义”或“数据现状”的标记。
3. **点“运行检查”。**
4. **看结果。** 通过率、通过数、未通过数；“只看未通过的”；每条显示不符合的行数和样例值。有问题的对象可以点编号，在对象浏览器里打开。

本体怎么推出期望：

| 本体里有 | 变成的期望 |
|---|---|
| 这个类型 | 至少有 1 个对象 |
| 主键，或名字像“类型名_id”的属性（复合主键就看组合不重复） | 不为空、不重复 |
| 标为必填的属性 | 不为空 |
| 属性类型（整数、数字、布尔、字符串、日期） | 取值符合类型 |
| 属性定义里写了取值集合、最小最大值、格式、唯一 | 照写的检查 |
| 外键（声明的，或导入时推断的） | 取值必须是被指向类型里已有的 |

导入演示数据时，数据管理员的业务规则（例如送达天数的范围、价格必填）已经写进属性定义，所以一运行就能看到“本体说了这样，数据却不是这样”。

注意：套件不是合法 JSON 会提示并且不发送；类型下没有对象会出黄色提示；超过 10,000 个对象只读前 10,000 个，并提示；对象多于 200 个的类型要先固定一份快照才能读完，只读账号做不了，会提示换有编辑权限的账号。

## 6. 实体消歧

找出指向同一个东西的多条记录：给每一对记录打匹配概率，概率够高的连成一个实体。

1. **选来源和类型。** 同上。默认选中的类型是有对象、数量适中、有名称或编号这类属性的那个。
2. **先看“重复的对象类型”**（本体模式）：哪几对类型像是同一个东西建了两遍。只提示，不合并。
3. **看比较方式，调阈值。** 展开“比较方式是怎么拟出来的”：每个属性怎么比、哪些属性没用上以及为什么。自动设置会这样选：

   | 属性像什么 | 怎么比 |
   |---|---|
   | 名称由多个词组成（如商品名） | 共同词占比分级（≥0.8、≥0.5、≥0.3） |
   | 人名 | Jaro-Winkler 相似度分级，常见名字的证据更弱 |
   | 编号、型号 | 去掉符号后一致、或只是多了后缀才算吻合；差一两个字符通常是另一个东西，不算相近 |
   | 日期、电话、邮编 | 编辑距离分级 |
   | 邮箱 | 看完整地址和用户名 |
   | 金额 | 相对差距 ≤2%、≤10%、≤30% 分级 |
   | 外键列、两边都有值的记录对不足 15% 的列、几乎每个对象一个值的列 | 不用，并写明原因 |

   有一列说明记录来自哪个来源（例如 `catalog_id` 只有两个取值）时，自动设置会**只在不同来源之间配对**（两家网店各有一份目录，同一家里的不同款不互相比较）。拖“匹配概率阈值”（默认 0.5，越高越保守）；有“真实分组列”（如 `true_entity`）时可以选，选“不打分”就不给精确率和召回率。
4. **点“运行实体消歧”。**
5. **看结果。** 精确率、召回率、F1；找到的实体数、最大一簇；“模型学到了什么”；匹配权重分布；“逐对解释”（拿不准的、错并、漏并、最确定的，每一对按字段列出权重）；“最大的几簇”（展开看成员，点编号打开对象）。最大的一簇占全部对象二十分之一以上时，上方会有“注意”提示。

**不适用的类型**：只有日期、金额、分类，没有名称、编号、邮箱、电话、地址的类型（例如订单行、传感观测），页面会直接说明“实体消歧不适用”和原因，而不是硬给一个没意义的结果。

## 7. 数据血缘

数据从哪来、经过哪些作业、流到哪去：画成图，点节点看详情，再问“改了它会影响谁”。

- **本体**：选本体就能看，导入的本体已经在最后一步生成好了血缘；“从本体生成血缘”可以重新生成（会替换上一次的）。图里依次是数据源 → 读取 → 原始表 → SQL 计算 → 导入建模 → 对象类型 → 规则 → 告警 → 处置，以及在类型上跑过的数据健康和实体消歧；按层着色，图上方有图例。TPC-H 的血缘有 31 个节点、48 条边、132 条列血缘。
- **示例文件**：点“载入 Marquez 外卖演示”（13 个作业、13 个数据集），“清除这份演示”可删掉。
- **看图**：点节点高亮它的上下游，点空白取消；右上的 `−`、`+`、“适应宽度”缩放；“只看所选节点附近”可选方向和跳数。
- **节点详情**：字段、SQL、最近运行、数据质量检查结果、列血缘；本体里的节点还有跳转链接（检查这个类型的数据健康等）。
- **影响分析**：“影响分析：它改了会影响谁”看整张表；本体模式下点字段旁的“影响”，看这一列会影响哪些下游列、哪些作业。

## 8. 流水线演示

同一份数据依次走：读入 → 数据健康 → 实体消歧，每一步记成血缘，最后得到一张图。

1. 选一个本体和一个对象类型（示例文件模式固定是 Splink 的 fake_1000）。
2. 点“运行流水线”；再点一次会重新跑一遍（同时重写这个本体的血缘）。
3. 看三张步骤卡、“三步是怎么连起来的”的说明，以及下面的血缘图。步骤卡里的链接会跳到数据健康、实体消歧页的同一个类型。
4. 选的类型没有可区分个体的属性时，实体消歧这一步显示“已跳过”和原因，其余两步照常运行。

都在“数据源”里一键导入。导入后在本体总览、对象类型、数据模型、数据分析里都能直接用。

| 演示 | 数据来源 | 类型 | 适合看什么 |
|---|---|---|---|

## 10. 五分钟演示路线

1. **首页**：看大屏，说明数字都是实时读的；点右上“数据源”。
2. **数据源**：点“供应链订单履约（TPC-H）”的“导入这份数据”，看每一步（约 3 秒）；完成后点“本体总览”“数据模型”，说明 12 个类型都在。
3. **数据血缘**：点卡片上的“数据血缘”，图里是数据源 → 读取 → 八张表 → 四个计算 → 本体 → 类型；点一个计算表看 SQL 和列血缘，再问“它改了会影响谁”。
4. **数据健康**：选 `OrderFulfillment` → 运行检查 → 看没通过的那条，点对象编号打开对象。
5. **实体消歧**：回数据源导入“商品主数据合并（Abt-Buy）” → 数据分析里选它，类型 `Product` → 展开“比较方式是怎么拟出来的” → 运行 → 看精确率召回率，展开“逐对解释”里的漏并和错并。
6. **流水线**：同一个类型点“运行流水线”，看三步怎么连起来。
7. **动态数据**：导入“出租车行程事件流”，点“推进 400 条”，回数据模型看对象增加。

## 11. 出问题怎么办

| 现象 | 怎么办 |
|---|---|
| 页面打不开 | `docker ps` 看 `p4int-frontend-1`、`p4int-backend-1` 是否在运行，不在就用第 1 节的命令 |
| 改了后端代码后接口报 500 | `docker restart p4int-backend-1` |
| 提示“另一个分析还在运行”或导入排队 | 同一时间只跑一个重计算、一个导入，等几秒再点 |
| 点运行或导入时提示没有权限 | 运行和导入需要有编辑权限的账号，只读账号只能看 |
| 大类型一直转圈 | 对象多于 200 个要分页读，几千个对象约十几秒；卡片上写着预计时间 |
| 同名本体已存在，导入被拒 | 点“重新导入”（会替换同名本体），或改个本体名称 |
| 类型标着“没有对象” | 类型建好了，对象还没进来 |
| 血缘图是空的 | 示例文件先点“载入 Marquez 外卖演示”；本体点“从本体生成血缘” |
| 导入完成了但“生成数据血缘”那步是红的 | 本体和对象已经建好；到数据血缘页点“从本体生成血缘”重试 |

## 12. 接口速查

都带 Bearer 令牌；运行、写入和导入需要编辑权限。

`/api/v2/ontology-imports`（数据导入）

| 功能 | 接口 |
|---|---|
| 演示数据集目录（含是否已导入） | `GET /bundles` |
| 导入一份演示数据 | `POST /bundles/{id}:import`，body `{"replace": false}`，返回任务 |
| 看任务进度 | `GET /jobs/{job_id}` |
| 上传文件并预览识别结果 | `POST /files`（多文件表单） |
| 导入上传的文件 | `POST /files/{upload_id}:import`，body `{ontology_name, replace, replay}` |
| 逐步载入的状态和推进 | `GET /{ontology_id}/replay`、`POST /{ontology_id}/advance` |
| 文件资产的内容 | `GET /{ontology_id}/assets/{asset_id}` |

`/api/v2/analysis`（数据分析）

| 功能 | 接口 |
|---|---|
| 平台总览（首页和选择器用） | `GET /overview` |
| 示例文件 | `GET /demos`、`GET /demos/{id}/preview`，以及不带 `/ontologies/{id}` 的 `health`、`resolution`、`lineage`、`pipeline` 同名接口 |

| 本体上的流水线、运行记录 | `POST /ontologies/{id}/pipeline/run`、`GET /runs`、`GET /runs/{id}` |
| OpenLineage 事件 | `POST /lineage/events` |

## 13. 现在的边界

- 数据健康、实体消歧、数据血缘是对三个开源项目做法的重写，数字是这套代码在这些数据上跑出来的，没有拿原项目对拍。
- Abt-Buy 的召回率只有一半：约五分之一的商品名称里没有型号，模型不敢下结论；这是诚实的结果。
- 实体消歧只出报告，不改本体；手工建的对象类型没有来源，血缘里没有它的上游。
- 一次最多导入 50 个对象类型和关系，同一时间一个导入；多于 10,000 个对象的类型只读前一部分。
- 本体的血缘是生成时的快照，本体、规则或告警变了要重新生成。
- 以后数据加工会换成 DuckDB 加 Dagster（老师团队的数据中台），现在只做了接口上的准备，见 ADR 0025；等中台的链接再接。
