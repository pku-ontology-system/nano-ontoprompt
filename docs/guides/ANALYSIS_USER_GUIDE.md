# 使用说明（简版）：数据分析功能与平台入口

> 2026-11-10 · 对应分支 `feat/meeting-demo-features`。只写现在侧栏里能点到的功能，暂时隐藏的入口见第 3 节末尾。设计和取舍见 [ADR 0022](../adr/0022-analysis-after-construction.md)、[ADR 0023](../adr/0023-analysis-on-platform-ontologies.md)。

## 1. 打开系统

| 要做什么 | 怎么做 |
|---|---|
| 打开 | 浏览器访问 <http://127.0.0.1:25173>，已登录就直接进入 |
| 登录 | 管理员账号写在项目根目录 `.env` 的 `FIRST_ADMIN_USER` 和 `FIRST_ADMIN_PASSWORD`，只在本机用 |
| 页面打不开 | 在项目根目录执行下面的命令，等约 1 分钟 |
| 改了后端代码 | `docker restart p4int-backend-1`（后端不会自动重载；前端会自动刷新） |

```bash
docker compose -p p4int -f docker-compose.yml -f docker-compose.local.yml -f docker-compose.p4int.yml up -d
```

端口 15173 和 18080 是另一套环境（p4dev），不要动。

## 2. 一句话

“数据分析”是侧栏的第四组，有四个页面：数据健康、实体消歧、数据血缘、流水线演示。每个页面顶部都有两个来源：

- **演示数据**：三个开源项目自带的数据文件（Great Expectations 的出租车数据、Splink 的人员记录、Marquez 的外卖业务血缘）；
- **本体里的对象**：平台里真实的本体，选一个本体，再选一个对象类型。

页面只做分析：检查、找重复、画血缘，不会修改本体。每次运行的结果都会存下来（接口 `/runs` 可查）。

## 3. 侧栏每个入口

| 入口 | 干什么 |
|---|---|
| 首页 | 工作区总览：三类数据的构建入口（时序、动态数据、多模态）、案例入口、最近本体、服务状态 |
| 本体库 | 全部本体的列表：创建本体，按 ID、名称、创建时间筛选，查看，删除（删除不能撤销） |
| 数据源 | 把数据导入当前本体：时序数据、多模态数据、业务数据（看已映射的数据集）、动态数据演示（用自己的演示本体） |
| 本体总览 | 当前本体的概况：对象类型、链接类型、运行规则、待处理告警的数量，以及每个对象类型（点“在对象浏览器中打开”看对象） |
| 对象类型 | 已发布的对象类型：属性、关系、真实记录、证据的数量；展开看记录和来源证据 |
| 数据模型 | 真实对象画成关系画布，可按类型筛选、分批加载；右侧是数据检查器 |
| 数据健康、实体消歧、数据血缘、流水线演示 | 见第 4 到 7 节 |
| 设置 | 通用、构建默认值、模型辅助、证据与质量、数据源、数据权限、数据平面、置信度规则、用户管理、服务主体、提示词模版 |

页面顶部的“当前本体”下拉决定数据源、本体总览、对象类型、数据模型看哪个本体；分析页的“本体里的对象”也默认用它，两边联动。右下角的“？”是应用自带的帮助。

侧栏里暂时隐藏了一批入口（对象浏览器、关系图、函数、情景推演、决策、规则、告警、Workshop、智能体等），页面都还在：地址后面加 `?nav=all` 全部显示（浏览器会记住），加 `?nav=default` 恢复。

## 4. 数据健康

用“期望”逐条检查一批数据：哪些列不能空、取值在什么范围、哪些值不该出现。每条期望说清有多少行不符合，并举出样例。

1. **选来源。** 演示数据：选一张卡片（默认是出租车 2019-01，里面有真实的脏数据），“看一眼数据”可看前 8 行。本体里的对象：选本体，再点一个对象类型卡片（卡片上写着属性数和对象数，没有对象的会标黄）。
2. **看“期望套件”。** 是一段 JSON，每条是 `{expectation_type, kwargs}`，可以直接改。本体来源的套件上方写着“共 N 条：X 条由本体推出”，每条结果带“本体定义”或“数据现状”的标记。
3. **点“运行检查”。**
4. **看结果。** 通过率、通过数、未通过数；“只看未通过的”；每条显示不符合的行数和样例值。本体模式下还有“有问题的对象”，点编号在对象浏览器里打开。

另有两个按钮：“恢复默认套件”；“按这份数据生成基线套件”（演示数据），本体模式下是勾选“再加上按现有数据生成的基线”后再运行。基线描述数据现在的样子，用来发现以后数据的变化。

本体怎么推出期望：

| 本体里有 | 变成的期望 |
|---|---|
| 这个类型 | 至少有 1 个对象 |
| 主键（Auto Ontology 记录的），或名字像“类型名_id”的属性 | 不为空、不重复 |
| 标为必填的属性 | 不为空 |
| 属性类型（整数、数字、布尔、字符串、日期） | 取值符合类型 |
| 属性定义里写了取值集合、最小最大值、格式、唯一 | 照写的检查 |
| 外键（声明的，或 Auto Ontology 推断的） | 取值必须是被指向类型里已有的 |

注意：套件不是合法 JSON 会提示并且不发送；类型下没有对象会出黄色提示（列上的期望没有数据可查）；超过 10,000 个对象只读前 10,000 个，并提示。

## 5. 实体消歧

找出指向同一个人（同一个东西）的多条记录：给每一对记录打匹配概率，概率够高的连成一个实体。

1. **选来源。** 演示数据：Splink 的 fake_1000（默认），或 5 万条历史人物（效果最好，约 10 秒）。本体里的对象：选本体和类型。
2. **先看“重复的对象类型”**（本体模式）：哪几对类型像是同一个东西建了两遍。每对有相似度、理由和建议（保留有对象的那个），可展开看属性怎么对上的。这里只提示，不合并。
3. **看比较方式，调阈值。** 展开“比较方式是怎么拟出来的”，看每个属性怎么比、哪些属性没用上；拖“匹配概率阈值”（默认 0.5，越高越保守：错并少、漏并多）；有“真实分组列”（如 `cluster`）时可以选，选“不打分”就不给精确率和召回率。
4. **点“运行实体消歧”。**
5. **看结果。** 精确率、召回率、F1；找到的实体数、最大一簇；“模型学到了什么”（每个字段每个一致程度的权重）；匹配权重分布；“逐对解释”（拿不准的、错并、漏并、最确定的）；“最大的几簇”（展开看成员，本体模式下点编号打开对象）。

## 6. 数据血缘

数据从哪来、经过哪些作业、流到哪去：画成图，点节点看详情，再问“改了它会影响谁”。

- **演示数据**：点“载入 Marquez 外卖演示”（13 个作业、13 个数据集；再点会替换上一次，不会重复），“清除这份演示”可删掉。
- **本体**：选本体，点“从本体生成血缘”（会替换这个本体上一次生成的）。图里依次是来源表 → Auto Ontology 生成 → 对象类型 → 规则 → 告警 → 处置，以及在类型上跑过的数据健康和实体消歧；按层着色，图上方有图例。手工建的类型没有上游，图里就没有。
- **看图**：点节点高亮它的上下游，点空白取消；右上的 `−`、`+`、“适应宽度”缩放；“只看所选节点附近”可选方向和跳数。
- **节点详情**：字段、SQL、最近运行、数据质量检查结果、列血缘；本体里的节点还有跳转链接（检查这个类型的数据健康、打开运行规则、告警中心、决策与影响链、AI 本体候选）。
- **影响分析**：“影响分析：它改了会影响谁”看整张表；本体模式下点字段旁的“影响”，看这一列会影响哪些下游列、哪些作业，以及多少条规则、告警和处置单。

## 7. 流水线演示

同一份数据依次走：读入 → 数据健康 → 实体消歧，每一步记成血缘，最后得到一张图。

1. 选来源：演示数据固定是 Splink 的 fake_1000；本体里的对象选一个本体和类型。
2. 点“运行流水线”；再点一次会重新跑一遍（本体模式下同时重写这个本体的血缘）。
3. 看三张步骤卡、“三步是怎么连起来的”的说明，以及下面的血缘图（可点节点、问影响）。步骤卡里的链接会跳到数据健康、实体消歧页的同一个类型。

## 9. 五分钟演示路线

地址可以直接粘贴到浏览器（前面都是 `http://127.0.0.1:25173`）。

1. **数据健康**：`/analysis/health?source=ontology&ontology=082581ac-3bf4-4698-9c46-52ceedba6f27&type=Person`
   运行检查 → 勾“只看未通过的” → 点一个对象编号，在对象浏览器里打开。
2. **实体消歧**：先看工厂本体的重复类型 `/analysis/resolution?source=ontology&ontology=07dcb4dd-baa4-4520-afa5-340a4c705570`，
   再看人员主数据 `/analysis/resolution?source=ontology&ontology=082581ac-3bf4-4698-9c46-52ceedba6f27&type=Person`：运行实体消歧，展开最大的一簇。
3. **数据血缘**：`/analysis/lineage?source=ontology&ontology=07dcb4dd-baa4-4520-afa5-340a4c705570`
   点“从本体生成血缘” → 点 FactoryAsset → 点字段 `t50_series` 旁的“影响”。
4. **流水线**：`/analysis/pipeline?source=ontology&ontology=082581ac-3bf4-4698-9c46-52ceedba6f27&type=Person` → 运行流水线。

## 10. 出问题怎么办

| 现象 | 怎么办 |
|---|---|
| 页面打不开 | `docker ps` 看 `p4int-frontend-1`、`p4int-backend-1` 是否在运行，不在就用第 1 节的命令 |
| 改了后端代码后接口报 500 | `docker restart p4int-backend-1` |
| 提示“另一个分析还在运行” | 同一时间只跑一个重计算，等几秒再点 |
| 点运行或生成时提示没有权限 | 运行和生成需要有编辑权限的账号，只读账号只能看 |
| 类型标着“没有对象” | 类型建好了，对象还没进来（例如 Auto Ontology 候选只发布了类型） |
| 血缘图是空的 | 演示数据先点“载入 Marquez 外卖演示”；本体先点“从本体生成血缘” |

## 11. 接口速查

都在 `/api/v2/analysis` 下，登录后带 Bearer 令牌；运行和写入需要编辑权限。

| 功能 | 接口 |
|---|---|
| 演示数据 | `GET /demos`、`GET /demos/{id}/preview` |
| 数据健康 | `GET /health/suites/{id}`、`POST /health/run` |
| 实体消歧 | `GET /resolution/presets/{id}`、`POST /resolution/run` |
| 血缘 | `POST /lineage/events`（OpenLineage 事件）、`POST /lineage/seed`、`GET /lineage/graph`、`GET /lineage/impact` |
| 流水线、运行记录 | `POST /pipeline/run`、`GET /runs`、`GET /runs/{id}` |
| 本体的对象类型 | `GET /ontologies/{id}/object-types` |
| 本体上的健康、消歧 | `GET /ontologies/{id}/health/suites/{type}`、`POST /ontologies/{id}/health/run`、`GET /ontologies/{id}/resolution/presets/{type}`、`POST /ontologies/{id}/resolution/run` |
| 重复的对象类型 | `GET /ontologies/{id}/duplicate-types`（可加 `?candidate_set=` 比较 AI 候选） |
| 本体的血缘 | `POST /ontologies/{id}/lineage/generate`、`GET /ontologies/{id}/lineage/graph`、`GET /ontologies/{id}/lineage/impact?node=&field=` |
| 本体上的流水线 | `POST /ontologies/{id}/pipeline/run` |

## 12. 现在的边界

- 这是对三个开源项目做法的重写，数字是这套代码在这些数据上跑出来的，没有拿原项目对拍。
- 手工建的对象类型没有来源，血缘里没有它的上游；必填、取值范围这类期望要类型定义里有人写了才会出现。
- 重复类型的得分权重是手拟的；实体消歧只出报告，不改本体。
- 本体的血缘是生成时的快照，本体、规则或告警变了要重新生成。
